# Research: 003 public SEO foundation

## Search title and description

**Decision**: One helper reads an optional per-locale override, then the same locale's visible title and a plain-text summary (excerpt, first body paragraph, or existing lead string). It never reads the other locale. Description is trimmed to about 160 characters. The document title keeps the existing `— Safe House` suffix.

**Rationale**: [spec.md](./spec.md) FR-001 and FR-002. `PageService::localizedMeta` falls back to Italian, which would leak an Italian sentence onto an English URL. [laravel-translatable](https://spatie.be/docs/laravel-translatable/v6/introduction) stores JSON translations; missing English must be detected with the locale argument that does not apply the package fallback.

**Alternatives**: A third-party SEO package (rejected — constitution prefers Laravel already in the app). Reusing `localizedMeta` (rejected — Italian fallback).

## Where editors type the override

**Decision**: CMS pages store `meta.seo_title.{locale}` and `meta.seo_description.{locale}` on the existing `pages.meta` array. Articles and donation campaigns get a nullable `seo` JSON column with the same shape. Filament `TextInput` ([text input](https://filamentphp.com/docs/4.x/forms/text-input)), max length 70 for title and 160 for description, labels in `lang/it/cms.php` and `lang/en/cms.php`. Home, donate hub, 5×1000, volunteer, and the two indexes have no extra editor; they use the existing per-locale headings and lead strings.

**Rationale**: FR-002 only requires an editor where a staff form already exists (pages, campaigns, news/editorial). Hubs already have Italian and English copy in `lang/*/site.php`.

**Alternatives**: New translatable columns on pages (rejected — `meta` already holds per-locale strings). One shared Site Settings blob for every URL (rejected — editors need per page).

## URL index

**Decision**: `GET /sitemap.xml` outside the locale prefix, `Content-Type: application/xml` ([responses](https://laravel.com/docs/13.x/responses)). Built on each request from published records. `lastmod` is `updated_at`. Replace `public/robots.txt` with `GET /robots.txt` that allows public crawling and prints `Sitemap:` plus the absolute sitemap URL ([routing](https://laravel.com/docs/13.x/routing)). The static file must go, or the web server will keep serving it and ignore the route.

**Included**: both locales of home, published CMS pages that have that locale's title, donations index, 5×1000, active campaigns and their privacy pages, news index and published news, editorial index and published articles, volunteer page.

**Excluded**: unpublished records, `/_preview/…`, donation thank-you, anything under `/cms-safehouse`.

**Rationale**: Reconciliation note in `.specify/progress/050-reconcile-003-public-seo.md`. Thank-you is a result page, not a document to rank. Campaign privacy is public only while that campaign is active.

**Alternatives**: A stored sitemap file regenerated by a job (rejected — publish already writes the database; a query is enough at this size). A sitemap package (rejected — no new dependency).

## Language alternatives and previews

**Decision**: In `<head>`, `link rel="alternate"` for `it` and `en` only when that locale has its own title. Fixed routes (home, hubs, volunteer) always have both. Also `link rel="canonical"` to the current absolute URL. Previews keep `X-Robots-Tag: noindex, nofollow` and gain `<meta name="robots" content="noindex, nofollow">`. They are not in the sitemap.

**Rationale**: FR-004 and FR-005. Visible `hreflang` on the footer is a user control, not a crawler alternative.

**Alternatives**: Always emit both locales (rejected — invents a missing translation). Drop the existing header (rejected — it already works).

## Share tags

**Decision**: `og:title`, `og:description`, `og:url`, `og:locale` (`it_IT` / `en_US`), and `og:image` when a content image already exists (first carousel slide or page background). Otherwise the existing logo. No new image upload field.

**Rationale**: FR-006. Articles and campaigns have no dedicated cover column today.

**Alternatives**: Require a new share-image upload (rejected — spec says use an image that already exists).
